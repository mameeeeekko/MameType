# 1.0.42 更新ログ

## 目的

1. **「ダウンロードボタンを押しても実際には保存されないのに、完了表示になる」問題の修正**
2. **オフライン用データのダウンロードを完全手動にする**（勝手に裏でDLしない）
3. **自動で出るアップデート促しモーダルの全廃**（ポップアップで更新を促さない）

---

## 症状と原因

### 「あっという間にダウンロード完了になる」

旧 `checkUpdateBtn` ハンドラは:

1. モーダル表示 → `await registration.update()`
2. `update()` の解決は「SWスクリプト取得＋差分比較」直後で、**ダウンロード完了ではない**
3. SW が最新だと `installing` も `waiting` も無い → else 分岐で
   **「最新版です。オフラインでも遊べます。」＋100%＋2秒後に閉じる**

→ 実ダウンロード 0 件で「完了」表示になっていた。

### 実際に保存されていない理由（複合）

| 場所 | 問題 |
|---|---|
| `service-worker.js` | `preCacheRemainingInBackground()` が `event.waitUntil()` に渡されておらず、SW のアイドル停止で途中終了する |
| 同 | 1件ずつ × 1.2秒間隔のため、195 + フォント413 = 約608件で 10分以上かかる設計 |
| 同 | `navigator.onLine === false` なら無言で即 return |
| `js/main.js` | 2秒後に `userInitiatedDownload = false` としてモーダルを閉じ、以降の進捗・結果を一切表示しない |
| 全体 | 完了検知・失敗検知・キャッシュ実在検証が無い |

---

## 修正内容

### 1. `js/main.js` — 手動DLをページ主導に作り直し

- `downloadOfflineData({force})` を新設:
  - 対象URLを最初に確定（`GET_OFFLINE_MANIFEST` + `OFFLINE_APP_FILES` + `collectOfflineAssetUrls()`）
  - `mametype-app`（html/css/js 約2.6MB）= 毎回全取得 / `mametype-assets`（約193MB）= 既存スキップ
  - 並列4、`fetch(url)` 既定（HTTPキャッシュ再利用で高速化）
  - 実測進捗: `％` ／ `取得 n ・ 既存 m ／ 全 N 件` ／ 現在のファイル名
  - **完了後に全URLを `caches.match(req, {ignoreVary:true})` で検証**し、欠落があれば「再試行」を出す
  - キャンセル（AbortController）対応、成功時のみ `_markCacheVersion(APP_VERSION)`
  - waiting SW があれば「更新を適用して再起動」ボタン（押したときだけ `SKIP_WAITING`）
- 自動モーダル系を削除: `showUpdateNotification` / `showUpdateReady` / `showOfflineReady` / `showUpdateProgressPreparing` / `autoApplyUpdate` / `handleUpdateProgress` / 推定進捗タイマー / `userInitiatedDownload` / `_showSwDownloadBar` 系
- `installed` / `complete` 検知は**設定 VERSION 欄のテキスト更新のみ**に変更

### 2. `service-worker.js`

- `install`: ブートコアキャッシュを廃止（オフライン環境で install が失敗して起動不能になる問題の根本修正）
- `activate`: 削除対象を旧 `mametype-v*` のみに限定（`mametype-app` / `mametype-assets` は保持＝版が上がってもDL済みデータが消えない）
- `GET_OFFLINE_MANIFEST` メッセージを追加（同一オリジンのURL一覧を `OFFLINE_MANIFEST` として返信）
- `preCacheRemainingInBackground()` / `START_OFFLINE_CACHE` / `BOOT_CORE_ASSETS` 参照 / `NON_BOOT_ASSETS_TO_CACHE` を削除
- `CORE_ASSETS` から `https://esm.sh/...`（クロスオリジン・キャッシュ不可）を除外

### 3. BGM/SE を「モード開始時読み込み」に変更

- `effectManager.js`: `registerSoundAssets()`（name→src の対応表を登録）と `ensureSound(name)`（未取得ならその場で fetch+decode、二重読み込み防止）を新設
- `playSE` / `playLoopSE` / `playBGM` / `fadeBGMTo`: `buffers[name]` が無い場合は `ensureSound` を開始してリターン（**初回1回だけ無音、2回目以降は鳴る**）。BGMは読み込み完了後に自動再生（世代管理で stopBGM 後の暴発を防止）
- `gameCore.js` / `enemyCore.js` / `defenseCore.js`: モード開始時に `await ensureSound(bgm)` を追加（先読みでBGM開始の遅れを最小化）
- `assetsLoader.js`: `loadRemainingAssets` から音声を除外（画像とフォントは従来どおり起動後に自動取得・フォント最優先）。`collectOfflineAssetUrls()` を新設（オフラインDL用のアセットURL一覧）

### 4. `online/loadSupabase.js` を新設

- `supabase.js` は `https://esm.sh` を**静的import**しており、これを `main.js` が静的にimportするとオフライン起動時にモジュール解決が失敗して**アプリ全体が起動できなくなる**
- `loadSupabase()` で動的importに閉じ込め、失敗時は `null` を返す（オンライン機能のみ無効化）
- `submitScore.js` / `getRanking.js` / `main.js`（Player IDインポートのRPC検証）も動的importへ変更

### 5. `index.html` / `style.css`

- オフラインDLモーダルに `#offlineDlDetail`（実測詳細）と `#offlineDlButtons`（操作ボタン）を追加
- `#update-notification` モーダルと `#swDownloadIndicator` バーを削除、関連CSSも削除
- `#remainingLoadIndicator`（起動時の画像/フォント読み込みバー）は維持

## 動作仕様（変更後）

| 項目 | 動作 |
|---|---|
| ページを開いたとき | モーダル無し。設定 VERSION 欄に `オンライン（実行中）: vX ／ オフライン用（手動DL済み）: vY` を表示 |
| 新バージョン検知 | テキストのみ（`新しいバージョン vZ があります`）。DL・適用はしない |
| 「最新版をオフライン用にダウンロード」 | このボタンを押したときだけDL。実測%・件数・ファイル名を表示、全件検証後に完了 |
| DL中の操作 | キャンセル可能 / 失敗時は再試行 / 完了時は OK（waiting があれば「更新を適用して再起動」も選択可） |
| SW 更新の適用 | **押したときだけ**再起動。勝手にリロードしない |
| 起動時の読み込み | 画像・フォントは裏で自動取得（従来どおり）。BGM/SE はモード開始時に読み込み |
