## v1.0.21 完了 — フォントサブセットの事前読み込み（タイピング表示遅延の完全解消）

### 症状と原因
- スタンダード / タイムアタック / 長文 / 防衛で「タイプしても表示が遅れる」が再発。エネミーモードは問題なし。
- v1.0.20 の SW 透明化は反映済み → SW は原因ではなくなっていた。
- 残る原因は**自己ホストフォントの遅延取得**:
  - `assets/fonts/fonts.css` はフォントを unicode-range サブセット（woff2 約200ファイル）に分割している
  - 各サブセットは**その文字を初めて表示した瞬間**に初めてネットワーク取得される（`font-display: swap`）
  - 漢字を含む問題（上記4モード）では問題が変わるたびに新サブセット取得待ちが発生 → 表示がフォールバック → 差し替え で遅延
  - エネミーモードの表示はほぼひらがな・ローマ字 → 最頻出サブセット（hiragana/ASCII）がすぐ揃うため問題が表面化しなかった

### 修正内容
1. **`js/assetsLoader.js`** — 裏読み込み（メニュー表示直後）で全フォントサブセットを事前取得:
   - `collectFontUrls()`: fonts.css を fetch して `url('./xxx.woff2')` をすべて抽出（相対パスは /assets/fonts/ 基準で解決、重複除去）。失敗しても起動は止めない
   - `prefetchFont()`: fetch + `arrayBuffer()` 消費で HTTP キャッシュに確実に載せる
   - 優先順位を **フォント → 画像 → 音声** に変更（フォントは軽いので 6 並列・4ms 間隔）
   - 進捗は既存の中央下「アセット読み込み中…」バーにそのまま集約
2. **`service-worker.js`** — バックグラウンド事前キャッシュの末尾にフォント取得を追加（オフライン対応の補完）。CACHE_NAME → `mametype-v1.0.21`
3. **`js/version.js`** → `1.0.21` / `CHANGELOG.md` → v1.0.21 追記

### 副作用の確認
- オンライン: フォントは HTTP キャッシュから即座に供給されるため、打鍵・問題切替時にフォント待ちが発生しない
- オフライン: SW キャッシュから配信されるため、日本語表示が正しいフォントで即時描画される
- SW の fetch ハンドラは**変更なし**（オンライン透明化のまま）
- 既存の「アセット読み込み中…」バーの進捗はフォント分を含めた総数で表示される（挙動は同じ）

### 確認手順
1. push → 反映（一度だけ `F12` → Application → Clear site data でもOK。以降は通常リロードで可）
2. メニュー表示直後に中央下バーが回る（フォント → 画像 → BGM）。完了を待たずにプレイ開始してOKだが、**完了後なら完全に即時表示**
3. スタンダード / タイムアタック / 長文 / 防衛で数問打ち、問題が変わっても表示が遅れないことを確認
4. エネミーモードが従来どおり問題ないことも確認
