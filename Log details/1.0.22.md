## v1.0.22 完了 — タイプ表示の遅れを「安定状態」へ復帰 + 更新フロー修正

### 症状
1. タイプ中に打っている文字の表示が遅れる（v1.0.21 のフォント事前読み込みでも解消しなかった）
2. 更新画面で「更新後、自動的に再起動します」と書いてあるのに再起動しない
3. 更新画面などの裏でキーバインド（キーショートカット）が発火する

### 原因（git 履歴との比較で特定）
安定状態（9/3 時点 `d553fa6`）と現在の差分:
- **安定状態**: `speedTick` が**毎フレーム `renderState()`** → `render()` は**同期**実行。表示は常に最新（最大1フレーム遅れ）
- **現在**: 9/9-10 の「軽量化」コミットで
  1. `speedTick` の毎フレーム描画を廃止 → **打鍵時のみ**描画（TA は250msスロットル）
  2. `gameCore.renderState` に rAF 遅延 + `renderer.render` にも**独立した rAF 遅延**（二重遅延・二重 pendingRender フラグ）
  → 打鍵の表示更新が2フレーム以上遅延し、負荷時はさらに遅れる。「打った文字の表示が遅れる」の正体

### 修正内容（安定状態への復帰）
1. **`js/renderer.js`** — `render()` を同期実行に戻す（内部の `pendingRender` + rAF を削除）
2. **`js/gameCore.js`** — `renderState()` を同期呼び出しに戻す（rAF 遅延を削除、未使用の `pendingRender` 変数も削除）
3. **`js/gameCore.js`** — `speedTick` で毎フレーム `renderState()` を復活。TA の 250ms 描画スロットルは廃止（`updateTimeAttack()` は毎フレーム呼びで OK、DOM 更新は秒変化時のみのまま）。`recordFrame` / `shouldRunFrame`（Low 品質の FPS キャップ）は維持
4. **`js/main.js`**（更新フロー）:
   - 「今すぐ更新」→ SKIP_WAITING。待機 SW 無し時は `update()` → `getRegistration()` 再確認 → それでも無ければ **0.8 秒後に自動 reload**
   - `controllerchange` 発生から **5 秒の安全タイマー**で強制 reload（文言どおり必ず再起動する）
5. **`js/main.js`**（ショートカット）:
   - `update-notification` モーダル表示中はキーを一切通さない（Escape/b → 「後で」）
   - `handleMenuKey` の 8 画面判定を `isScreenVisible()`（getComputedStyle ベース）に変更

### 変更ファイル

- 描画は毎フレーム（安定状態と同じコスト）。ただし `renderNormal` のローマ字再構築にはキャッシュがあり、`updateTimeAttack` の DOM 更新は秒変化時のみのため、低スペックでも実用上問題なし
- エネミー/防衛モードのゲームループは変更なし（エネミーモードの快調さを壊さない）
- v1.0.21 のフォント事前読み込みは維持（打鍵中のフォント取得待ちも同時に防止される）
