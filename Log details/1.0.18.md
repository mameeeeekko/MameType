## 修正完了（v1.0.18）

### 根本原因と修正内容

**エラーB（決定的バグ）: `cannot access CORE_ASSETS before initialization at service-worker.js:75:25`**

```
old) 75: const DEFERRED_ASSETS = CORE_ASSETS.filter(   ← CORE_ASSETS がまだ未定義
     79: const CORE_ASSETS = [...]                     ← 後で定義
```

前回の WIP（v1.0.16）で追加された `DEFERRED_ASSETS` が、**後に宣言される `CORE_ASSETS` を先に参照**していました。`const` は一時的デッドゾーン（TDZ）のため、SW スクリプトの評価がここで **ReferenceError → スクリプト全体が失敗 → SW 登録不能**になります。

- ✅ `DEFERRED_ASSETS` は**どこからも使われていない未使用コード**だったため削除しました。これで `CORE_ASSETS`（現在79行）への前方参照が一切なくなり、SW が正常に評価・登録されます。

**エラーA: `failed to fetch at service-worker.js:545:16`（ハードリセット前）**

壊れた SW が**制御権を握ったまま**ページのリクエストを横取りし、その後に失敗する連鎖でした（tdz のため SW が最初の1行目で死ぬのに、ブラウザは古い壊れ方をした SW を保持し続ける）。v1.0.18 の有効な SW が入れば、install 時の各アセットの fetch 失敗は**ファイル単位で catch（file-error 通知）**され、ページ側や install 全体を止めません。

### 追加の堅牢化

- **`notifyClients()` を防御化** — 閉じられたクライアントへの `postMessage` 失敗で install の進捗通知チェーンが中断しないようにしました

### Windows での確認手順

1. push して GitHub Pages に反映
2. Windows でページを開く（必要なら **一度だけ `Ctrl+Shift+R`** で古い壊れSWを追い出す）
3. 正常に起動 → 中央下に「オフラインデータをダウンロード中 N%」バー → 完了で「オフラインでも遊べるようになりました 🎮」
4. 以降は通常リロードで起動し、更新時は中央下バー → 「今すぐ更新」通知（バーなし）の流れになります

補足: 壊れた SW が一度ブラウザに入ると、その SW を参照し続けるブラウザでは修正版でも最初の1回は再取得が必要なことがあります（OS やブラウザのキャッシュ仕様による）。「ハードリセットしないと起動しない」が解消しない場合は、`F12` → Application → **Clear site data**（または Unregister service worker）を一度実行してください。
