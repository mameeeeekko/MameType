## 補足： size-adjust について

前回おすすめで触れた `size-adjust` の細部改良は、**今回は適用していません**。理由は、`@font-face` は自己ホストしたフォントにしか効かず、フォールバック先の OS 標準フォント（Hiragino / Yu Gothic UI / Meiryo）は `@font-face` で調整できないためです（無理に入れると、丸ゴ自体のサイズが変わってしまい、Mac / Windows 両方の見た目がズレます）。代わりに、フォールバックの順序を整える（丸ゴ → Noto Sans JP → Hiragino → Yu Gothic UI → Meiryo）方式で「化けた時の見た目」を整えました。

## 今回の修正内容

### Windows 起動エラーの原因（特定）

報告の「sound のエラー」から、**起動を妨げていた構造的欠陥**が見つかりました：

`js/effectManager.js` の `getAudioContext()` が `new AudioContext()` を**例外処理なし**で呼んでおり、Windows でオーディオデバイスが無効（オーディオサービス停止、音声ポリシー制御中、ドライバ不調など）だと例外が発生 → `initAudio()` が失敗 → `loadCoreAssets()` が失敗 → **ブート画面から先に進めずゲームが開けない**、という連鎖でした（Mac ではオーディオが正常なので起きません）。

### 修正内容（音なしでも必ず起動するように）

1. **`getAudioContext()` を安全化** — AudioContext 未対応・生成失敗・オーディオグラフ構築失敗のいずれでも例外を握りつぶし `null` を返して「音なしモード」へ
2. **`initAudio()`** — ctx が null なら初期化完了扱いにしてゲーム起動を止めない
3. **`loadSound()`** — 音源の取得失敗（HTTPエラー）・デコード失敗を catch し、1音源の失敗で全体が止まらないように
4. **全10箇所の再生関数**（playTone / playNoise / playSE / playTypeSound / playLoopSE / playBGM ほか）に `if (!ctx) return;` ガードを追加 — 音なしモードで再生呼び出しが例外を投げない
5. **v1.0.14 にバージョン更新**（version.js / service-worker.js / CHANGELOG）— SW はキャッシュ優先なので CACHE_NAME を変えないと Windows に修正が届きません

### 「analytics.js の js1 のブロック」について

analytics.js は AdBlock 等で gtag.js がブロックされても例外を握りつぶす設計なので、**このエラーは無害**（ゲームの起動には影響しません）です。多くの場合「blocked by client」= AdBlock / プライバシー拡張によるもので、無視してOKです。

## 確認方法

1. push 後、Windows でページを開く
2. 「更新準備完了」が出たら「今すぐ更新」（または `Ctrl + Shift + R`）
3. ブート画面 → メニューが表示されれば起動復旧完了です。音が出ない環境でもゲーム自体は遊べるはずです
