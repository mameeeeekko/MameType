## v1.0.20 完了 — オンライン中は SW を完全に透明化

### 今回の判断と理由

あなたの Windows 上のエラーは、**ページ本体の要求は GitHub から普通に届くのに、SW 経由の fetch だけ必ず失敗する**という環境固有の症状でした（プロキシ・セキュリティソフト等が SW コンテキストの fetch を妨げるケース）。

これまで状況が改善しなかった唯一の理由は、fetch ハンドラが**オンラインでも全リクエストを SW 経由**にしていたことです。そこで逆転の発想で:

| 状態 | SW の動作 |
|------|----------|
| **オンライン** | **一切介入しない**（`respondWith` も呼ばない → ページは SW が無いのと同じ速度で直通） |
| **オフライン** | 初めてキャッシュから配信（なければオフライン用 503） |

これにより：
- ❌ `failed to fetch` / `no cached response` → **オンライン中は発生し得なくなりました**
- ❌ タイピング表示の遅延 → **フォント・JS が直接ネットワークから読み込まれるため解消**（スタンダードの日本語表示がフォールバック描画になることもなくなります）
- ✅ オフライン対応 → install の起動コア + activate 後のバックグラウンド事前キャッシュ（`ONLINE` のときだけ実行）で、落ちたらキャッシュから再生
- ✅ 更新通知・「今すぐ更新」・中央下の進捗バー → 従来どおり動作

1. push → 反映
2. 一度だけ **`F12` → Application → Unregister（または Clear site data）** → リロード
   （前回の壊れた SW の登録を確実に消すため。以後は不要です）
3. 以降は**通常リロードだけで起動**し、タイピングが**即時**反応するはずです

万が一まだ従来のラグが残る場合は、SW が原因でなく**フォント描画やエフェクト側**の問題なので、次の一手としてそちらの特定に入れます。
